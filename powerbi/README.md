# Power BI Project (.pbip)

`OmnichannelRetail.pbip` is the full semantic model as code — generated by
[`scripts/build_pbip.py`](../scripts/build_pbip.py) from the CSV schema and
[`model/measures.dax`](../model/measures.dax):

- 10 tables with their Power Query sources and typed columns (incl. the `dim_month` bridge and the hidden `_Measures` table)
- 12 single-direction relationships
- `dim_date` marked as the date table; Auto date/time disabled
- 54 measures with display folders and format strings
- a report with the five pages from [`report/report_spec.md`](../report/report_spec.md), empty and ready for visuals

## Open it (10 minutes to a working model)

1. **Power BI Desktop** (2025 or later). If `.pbip` files do not open, enable
   *File → Options → Preview features → "Power BI Project (.pbip) save option"* and
   *"Store semantic model using TMDL format"*, then restart Desktop.
2. Clone this repo (or download it) so that `data/star_schema/` is on your disk.
3. Open `powerbi/OmnichannelRetail.pbip`.
4. Desktop will say the model needs data. Go to **Transform data → Manage parameters → DataFolder**
   and set it to the absolute path of your `data/star_schema/` folder **with a trailing backslash**,
   e.g. `C:\Users\anh\repos\omnichannel-retail-powerbi\data\star_schema\`. Close & Apply.
5. When asked about privacy levels, choose *Ignore privacy levels* for this file (local CSVs).
6. **Refresh**. Expect 20–40 s (548k sales rows, gzip decompressed in-query).
7. Sanity check: a card with `[Net Sales]` filtered to `dim_date[year] = 2025` must show
   **118,171,760,000**; `[Target Achievement %]` must show **97.8%**.
8. Apply the theme: *View → Themes → Browse for themes → `report/theme.json`*.
9. Build the visuals page by page from the spec, then **File → Save as → .pbix** into `report/`
   and commit it together with screenshots.

## If something does not load

| Symptom | Fix |
|---|---|
| "File not found" on refresh | `DataFolder` path wrong or missing the trailing `\`. Check in *Manage parameters*. |
| `Binary.Decompress` error on `fact_sales` / `fact_inventory` | Unzip the two `.csv.gz` files and, in `fnLoadCsv`, change `gzipped` to `false` for those two tables (or edit the partition sources to the `.csv` names). |
| Column type error | Run `python data/generate_data.py` to regenerate the CSVs — the model expects exactly those columns. |
| A measure shows an error | Open it in the formula bar; the DAX is identical to `model/measures.dax`, where the intent is commented. |
| Desktop refuses the `.pbip` | Report the version and the message as an issue; the fallback is the manual route in [`docs/build_guide.md`](../docs/build_guide.md), which uses the same `power_query.pq` and `measures.dax`. |

## Regenerate

```bash
python scripts/build_pbip.py
```

Lineage tags are regenerated on every run (new GUIDs), so only rebuild when the schema or the
measures change, and commit the result in the same change.

## Why a project, not just a .pbix

A `.pbix` is a binary blob: no diffs, no review, no reuse. The TMDL project is readable text — a
measure change is a one-line diff, the model can be reviewed in a pull request, and the same
definition can be deployed with Fabric Git integration. The `.pbix` is the artefact for users; the
`.pbip` is the artefact for engineers.
